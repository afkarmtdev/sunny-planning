FUNCTIONALITY NOTES
  • Shown briefly on cold app launch while auth/session state and the shared space's data (mascot happiness, upcoming date) are fetched.
  • Sunny should hop/blink in a small idle loop the whole time this is on screen (see lg-hop keyframe already defined in this file).
  • On success, route to Home if a session exists, or to Login if not. On a paired-but-not-yet-invited account, route to Invite Partner instead.
  • Should have a hard timeout (e.g. 4 to 6 seconds) that falls through to Login with an error state rather than hanging indefinitely offline.
00b · Loading
fetching your next date...
FUNCTIONALITY NOTES
  • This is a shared, reusable component, not just a standalone screen. It should mount as a translucent overlay on top of ANY screen (Home, Itinerary Builder, Cost Tracker, etc.) whenever that screen is waiting on a backend fetch or mutation, rather than only appearing full-screen at cold launch. See the overlay variant to the right for how it sits on top of existing content.
  • As an overlay: dim the screen behind it with a semi-transparent cream/ink scrim, keep the card centered, and block taps to the content underneath until the request resolves.
  • The three dots hop in a staggered sequence (already offset via animation-delay) rather than all bouncing in sync.
  • Caption text should change per context ("fetching your next date...", "saving your itinerary...", "packing up your PDF...") rather than being one fixed string.
  • For actions under roughly 300ms, prefer no loading state at all (or a lighter inline spinner) so this full-screen moment doesn't flash for instant operations.
  • Should be interruptible: a cancel affordance may be warranted for long-running actions like PDF export, though not shown in this mockup.

FUNCTIONALITY NOTES
  • This is the same loading component as 00b, shown mounted over Home as an example. The underlying screen is blurred, dimmed, and non-interactive (pointer-events disabled) while it is visible.
  • Content behind the scrim does not need to be real; it should simply be whatever the previous screen state was, frozen in place, so the transition doesn't feel jarring.
  • Recommend a short fade-in delay (roughly 150 to 250ms) before showing this overlay, so quick responses never flash it.
  • On success, fade out the overlay and reveal the updated content underneath. On failure, replace the overlay with an inline error state and a retry action rather than leaving Sunny hopping indefinitely.
